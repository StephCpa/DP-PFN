  Summary
  DP-PFN is feasible and has a sound theoretical basis, because PFN weights cost no
  privacy budget. The central caveat: a trained PFN cannot be certified from its training
  loss. Guarantees must therefore come from black-box wrappers or from noise-aware use
  of already-private data.

  1. Setup: what is private and what is free
  In DP-PFN the network weights depend only on synthetic prior data. They therefore cost
  no privacy budget, and every privacy question concerns the context D and what is
  released from it.

  Records and prior. A record is z = (x, y) with x in a feature space X and y in K classes. The
  context is D = (z_1, ..., z_n), and a query is x*. The prior draws a task parameter φ ~ π, then
  records i.i.d. from p(z | φ).

  Target and objective. The posterior predictive distribution (PPD) and the PFN training
  loss are:

     P(y \mid x^*, D) = \int p(y \mid x^*, \varphi)\, \pi(\varphi \mid D)\,
     d\varphi, \qquad \pi(\varphi \mid D) \propto \pi(\varphi) \prod_{i=1}^{n}
     p(z_i \mid \varphi)


     \mathcal{L}(\theta) = \mathbb{E}_{\varphi, D, x^*, y^*}\big[-\log
     q_\theta(y^* \mid x^*, D)\big] = \mathbb{E}_{D, x^*}\,
     \mathrm{KL}\big(P(\cdot \mid x^*, D)\,\|\, q_\theta(\cdot \mid x^*, D)\big) +
     \text{const}


  The second identity is the PFN theorem of Müller et al. (2022). It matters below: the PFN
  is only trained to be close to the PPD on average over prior-drawn datasets.

  Neighbouring relations. DP-PFN must say which change to the data it protects against.

  Release modes. We study three ways outputs leave the system.

          R1, prediction API. k possibly adaptive queries are answered from D. Privacy
          composes over k.
          R2, student-context release. One privately labelled context is published once.
          Anyone can then run the public PFN on it, as post-processing, with no further cost.
          R3, noise-aware release. A DP summary S = M(D) is published (noisy statistics,
          randomized-response labels, DP synthetic rows, noisy graph aggregates). A PFN
          trained to read S does the inference.

  Proposition 0 (free weights). Suppose θ is statistically independent of D. Then for any
  mechanism A, the map D ↦ A(q_θ, D) has exactly the privacy of A run with q_θ as a fixed
  public function. All accounting therefore concerns the context alone.

  Proposition 0 fails in two practical cases, and DP-PFN must rule both out:

      1. Real-data checkpoints. Weights fine-tuned on real tables are no longer free. DP-PFN
          should use synthetic-only checkpoints.
      2. Data-dependent preprocessing. Standardization, quantile transforms or PCA fitted
         on the private context are themselves releases. They must use public feature bounds
         or be privatized and counted in the budget.

  The prior designer must also not tune the prior on the private dataset, since that would
  make θ depend on D.


  2. Theory A: one draw from the exact PPD is already DP
  If every record's likelihood has bounded oscillation B under every task, one draw from the
  exact PPD is 2B-DP. B is finite only if the prior is designed that way. That design can be
  simulated, so a PFN can be trained on it.

  Definition A1 (oscillation). For records and for labels:

     B = \sup_{\varphi}\Big[\sup_{z}\log p(z\mid\varphi) - \inf_{z}\log
     p(z\mid\varphi)\Big], \qquad B_y = \sup_{\varphi, x}\Big[\max_{y}\log p(y\mid
     x,\varphi) - \min_{y}\log p(y\mid x,\varphi)\Big]




                                                                                              Page 3 of 25
DP-PFN: Differentially Private Prior-Data Fitted Networks




  Theorem A2 (posterior and PPD sampling). Let D ≃ D' be replace-one neighbours and B <
  ∞. Then for all φ, x* and y:

     \pi(\varphi\mid D) \le e^{2B}\,\pi(\varphi\mid D'), \qquad P(y\mid x^*, D)
     \le e^{2B}\, P(y\mid x^*, D')


  So releasing φ ~ π(· | D), or y ~ P(· | x*, D), or any function of either, is 2B-DP. For label
  neighbours the same holds with B_y.

  Proof. Let D' replace z_j with z_j', and let L(φ) be the product of the other n − 1 likelihoods.

     \frac{\pi(\varphi\mid D)}{\pi(\varphi\mid D')} = \frac{p(z_j\mid\varphi)}
     {p(z_j'\mid\varphi)}\cdot\frac{Z(D')}{Z(D)}, \quad Z(D') = \int \pi L\,
     p(z_j'\mid\varphi)\, d\varphi \le e^{B}\int \pi L\, p(z_j\mid\varphi)\,
     d\varphi = e^{B} Z(D)


  Both factors are at most e^B. The PPD mixes the same kernel p(y | x*, φ) over the
  posterior, so the bound carries over. If x* is itself informative about φ, condition the
  posterior on x* as well; x* is common to both sides, so the bound is unchanged. ∎

  This is the "privacy for free" result of Dimitrakakis et al. (2014) and Wang, Fienberg &
  Smola (2015). They state 4B because they bound |log p| ≤ B, which is an oscillation of 2B.

  Why standard PFN priors give B = ∞.

          Features. Priors that generate x and y jointly from a structural causal model (as
          TabPFN's does) use continuous feature densities. Their log-density is unbounded, so
          B = ∞ for row-DP.
          Labels. If any class probability can approach 0, then B_y = ∞.

  Definition A3 (floored prior). Mix each likelihood with a strictly positive reference. Here r
  is uniform on a bounded feature domain, and p(z | φ)/r(z) ≤ M.

     p_\alpha(z\mid\varphi) = (1-\alpha)\,p(z\mid\varphi) + \alpha\, r(z), \qquad
     p_\eta(y\mid x,\varphi) = (1-\eta)\,p(y\mid x,\varphi) + \eta/K


  Lemma A4. B(p_α) ≤ log(1 + (1 − α)M/α) and B_y(p_η) ≤ log(1 + K(1 − η)/η).

  Floors can be simulated; tempering cannot. A floored likelihood is a mixture, so data can
  be drawn from it: with probability η, resample the label uniformly. A PFN can therefore be
  trained on the floored prior, with η as an input token, which makes ε a dial set at inference
  time. A tempered posterior π(φ) Π p(z_i | φ)^τ corresponds to no data-generating
  process, so a PFN cannot be trained on it directly.

  Theorem A5 (a clean-target PFN draws one posterior sample). Train with η-noisy context
  labels but clean query targets h_φ(x*) = argmax_y p(y | x*, φ). The loss minimizer is Q(y |
  x*, D) = π(h_φ(x*) = y | D). Sampling from Q is post-processing of one posterior draw,
  hence 2B_y-label-DP. Unlike sampling the noisy PPD, Q contains no η label noise. Where
  the posterior is consistent, Q concentrates on the Bayes decision as n grows, while ε stays
  fixed. T1 (Section 9) asks how fast, when η misstates the real label noise.

  Theorem A6 (many labels for the price of one). Let the PFN also accept context tokens
  flagged "clean pseudo-label". At public query points x_1, ..., x_m, sample ŷ_1 ~ Q(· | x_1, D),
  then ŷ_2 ~ Q(· | x_2, D, (x_1, ŷ_1)), and so on. If every conditional is exact, the chain rule
  gives:

     (\hat y_1,\dots,\hat y_m) \overset{d}{=}
     \big(h_\varphi(x_1),\dots,h_\varphi(x_m)\big), \qquad \varphi \sim
     \pi(\cdot\mid D)


  The whole labelled student context is post-processing of one posterior draw. It costs 2B_y
  in total, whatever m is. This is an exact-case DP reading of predictive resampling, as in
  martingale posteriors (Fong, Holmes & Walker, 2023). In release mode R2, it makes cost
  independent of the student-context size, whereas noisy-vote labelling (PATE) pays per
  label.

  Theorem A7 (amplification by subsampling). Run any of the above on m records drawn
  without replacement from n. An ε-DP base mechanism becomes log(1 + (m/n)(e^ε − 1))-
  DP (Balle, Barthe & Gaboardi, 2018). PFNs take subsampled contexts natively, so this
  costs nothing extra. The last column of the table above uses it.

  Exactly solvable test beds. Beta–Bernoulli, Dirichlet–categorical and Gaussian-process
  priors have closed-form posteriors. Geumlek, Song & Chaudhuri (2017) give tight Rényi-DP
  bounds for exponential families. These let us compare a trained PFN with the exact
  mechanism (Section 3).

  3. Theory B: the amortization gap
  A PFN is trained to match the PPD on average, while DP is a worst-case condition. So no
  bound on training loss can certify that a trained PFN is DP. A certificate must come from
  the network's own row sensitivity, or from a mechanism whose guarantee does not
  depend on the network at all.

  Per-dataset approximation error.

     \Lambda(D) = \sup_{x^*, y}\big|\log q_\theta(y\mid x^*, D) - \log P(y\mid
     x^*, D)\big|, \qquad \Delta(D) = \sup_{x^*}\mathrm{TV}\big(q_\theta(\cdot\mid
     x^*, D),\, P(\cdot\mid x^*, D)\big)


  Lemma B1 (transfer). Suppose sampling from the exact PPD is ε-DP.

          If sup_D Λ(D) ≤ λ, sampling from q_θ is (ε + 2λ)-DP.
          If sup_D Δ(D) ≤ γ, sampling from q_θ is (ε, (1 + e^ε)γ)-DP.

  Proof of the second. For any event S: q(S | D) ≤ P(S | D) + γ ≤ e^ε P(S | D') + γ ≤ e^ε q(S |
  D') + (1 + e^ε)γ. ∎

  Proposition B2 (training loss cannot certify DP). The loss L(θ) sees q_θ only on datasets
  of positive prior probability. Changing q_θ on any prior-null set of datasets leaves L(θ)
  unchanged. With continuous features every single dataset is prior-null, including any pair
  D, D' an adversary chooses. So for every attainable loss value, some predictor attains it
  and reveals a row deterministically on a chosen D, violating (ε, δ)-DP for every finite ε and
  δ < 1.

  Even on a set A of positive mass ν, replacing q by (1 − κ)·(point mass) + κ·P on A raises the
  loss by at most ν log(1/κ). The sup in Lemma B1 is therefore something the training
  objective never controls.

  Proposition B3 (certify the network, not its accuracy). Define the network's own row
  sensitivity:

     s(\theta, n) = \sup_{D\simeq D',\, x^*,\, y}\big|\log q_\theta(y\mid x^*, D)
     - \log q_\theta(y\mid x^*, D')\big|


  Sampling from q_θ is then s-DP, with no reference to the PPD.

          Output floor (trivial regime). Mixing the output with uniform η/K gives s ≤ log(1 + K(1
          − η)/η) for any change to the whole context. This is randomized response on the
          prediction. It is private, but ε never shrinks with n.
          Useful regime. We want s = O(C/n), so each row's influence decays as the context
          grows. Consider one attention readout whose logits lie in [−R, R], for example by
          LayerNorm plus spectral-norm limits. Each attention weight is then at most e^{2R}/n,
          and replacing one row moves the readout by O(V e^{2R}/n), where V bounds the
          value norms. Layers in which context rows attend to each other compound the
          constant roughly geometrically in depth. Dot-product attention is not globally
          Lipschitz (Kim, Papamakarios & Mnih, 2021), so bounded inputs or L2 attention are
          needed.

  Certified constants for a full TabPFN-scale network will be loose. B3 is realistic for a small
  "certifiable DP-PFN" used in theory, and as a basis for data-dependent methods such as
  propose-test-release.

  Corollary B4 (design rule). Place the PFN inside a mechanism whose guarantee holds for
  any black box (Section 4), or let it read only a privatized summary (Section 5).
  Approximation error then costs utility, never privacy. Exact-PPD mechanisms (Section 2)
  serve as closed-form test beds and as the target that audits measure against.

  Observation B5 (leakage partly reflects Bayes-optimality). Under a low-noise prior B_y
  is large, so the exact PPD on small n already depends strongly on single rows. A PFN that
  approximates it well inherits that dependence. Membership attacks on tabular foundation
  models therefore partly measure faithfulness to a non-private target. Examples are
  AMIA's attention-concentration signal (Carvalho & Cordy, 2026) and the attacks in
  TabPATE.

  Prediction: better PFNs leak more unless the target itself is private. Experiment E1
  (Section 10) tests this on closed-form priors, where the exact privacy loss is known.



  4. Theory C: black-box DP-PFN mechanisms
  The robust route treats the PFN as a free, near-Bayes-optimal teacher inside a mechanism
  whose guarantee holds for any black box. PFNs strengthen these mechanisms where they
  are weakest: small shards.

  Mechanism C1 (DP-PFN-Vote, private prediction).

      1. Split D at random into T disjoint shards of size m = n/T. The split must not depend on
         the data.



                                                                                             Page 7 of 25
DP-PFN: Differentially Private Prior-Data Fitted Networks




      2. Teacher t predicts ŷ_t = argmax_y q_θ(y | x*, D_t). This is one forward pass, with no
         training.
      3. Release the noisy argmax of the vote counts c_y(x*).

  Replacing one row changes one shard, so the vote histogram moves by at most 1 in two
  coordinates (ℓ₂ sensitivity √2). Report-noisy-max with Laplace(2/ε) noise is ε-DP per
  answer. Gaussian noise of scale σ gives Rényi-DP α/σ² per answer, as in PATE's GNMax.
  Answers compose, and PATE's data-dependent analysis charges far less when teachers
  agree.

  Theorem C2 (shard-level accuracy sets the DP sample size). Take binary labels. Disjoint
  shards are independent draws, so teachers are independent given the data distribution.
  Let e(m) be one teacher's error at shard size m, with margin γ_m = 1 − 2e(m) > 0. Then C1
  with Laplace(2/ε) noise answers correctly with probability at least 1 − β whenever:

     T \;\ge\; 8\log(2/\beta)\cdot\max\Big\{\frac{1}{\gamma_m^2},\; \frac{1}
     {\varepsilon\,\gamma_m}\Big\}, \qquad n^* = \min_m\; m\cdot T(m)


  Proof. By Hoeffding, the vote margin falls below Tγ_m/2 with probability at most
  exp(−Tγ_m²/8). Two Laplace(2/ε) draws overturn a margin of Tγ_m/2 with probability at
  most exp(−εTγ_m/8). Set each term to β/2. ∎

  Privacy enters only through T. A teacher that is more accurate at small m has a larger γ_m,
  which lowers n*. PFNs are built for this small-data regime. PATE-style trained teachers
  degrade at small m, and each one must also be trained.

  Mechanism C3 (DP-PFN-LogPool, a Bayes-consistent soft aggregator). Under the prior,
  shard posteriors combine exactly as π(φ | D) ∝ π(φ)^{1−T} Π_t π(φ | D_t). The Bayesian
  committee machine (Tresp, 2000) applies the same rule to predictives. Floor each
  teacher's output at η/K, then sample from an exponential mechanism over the pooled
  score:

     S_y(x^*) = \sum_{t=1}^{T} \log \tilde q_\theta(y\mid x^*, D_t) - (T-1)\log
     q_\theta(y\mid x^*, \varnothing), \qquad \Pr[\hat y = y] \propto
     \exp\!\Big(\frac{\varepsilon\, S_y}{2\log(K/\eta)}\Big)


  The floored log-probabilities lie in an interval of width at most log(K/η). The prior-
  correction term does not depend on the data. So one shard change moves each S_y by at
  most log(K/η), and the sampler is ε-DP. As ε grows, it approaches the committee-machine
  argmax.




                                                                                           Page 8 of 25

  Unlike hard votes, LogPool keeps each teacher's confidence. That helps exactly when
  teachers are calibrated, which PFNs tend to be. When LogPool beats Vote is open
  question T4 (Section 9).

  Mechanism C4 (DP-PFN-Student, release mode R2). Label N public or synthetic queries
  with C1 or C3, and publish them as a student context. Every later prediction is post-
  processing. TabPATE follows this design, with synthetic queries drawn from feature
  ranges. DP-PFN adds two options:

          Draw queries from the PFN's own prior, so query generation never touches the data.
          In the exact regime, replace per-label noisy votes with Theorem A6's single-draw cost.

  5. Theory D: noise-aware DP-PFN
  Suppose the data leave the owner through a public DP mechanism M. Putting M inside the
  prior turns the PFN into the Bayes-optimal analyst of the privatized data. Its privacy is
  exactly that of M, whatever the network's approximation error. This is the cleanest
  combination of the two theories.

  Construction. Draw φ ~ π, D ~ p(· | φ), S ~ M(D) and a query pair (x*, y*) ~ p(· | φ). Train
  q_θ(y* | x*, S), with S tokenized as the context. The mechanism's type and parameters (ε,
  σ, flip rate) are input tokens, so one network covers a family of mechanisms.



                                                                                                             Page 9 of 25
DP-PFN: Differentially Private Prior-Data Fitted Networks




  Theorem D1 (target, privacy, optimality).

      1. The loss minimizer is the private-data PPD. Its posterior is intractable by classical
         means (Williams & McSherry, 2010; Bernstein & Sheldon, 2018; Ju et al., 2022).

             P(y^*\mid x^*, S) = \int p(y^*\mid x^*, \varphi)\,\pi(\varphi\mid S)\,
             d\varphi, \qquad \pi(\varphi\mid S) \propto \pi(\varphi)\int M(S\mid D)\,
             p(D\mid\varphi)\, dD


      2. Every q_θ(· | x*, S) inherits M's (ε, δ) guarantee by post-processing, whatever its
         approximation error. Prediction queries are then free and unlimited.
      3. Among all predictors that see only S, the target has the least expected log-loss under
          the prior. Its excess over the non-private Bayes predictor is exactly a conditional
          mutual information:

             H(y^*\mid x^*, S) - H(y^*\mid x^*, D) = I(y^*; D\mid x^*, S) \;\ge\; 0


  Proof of 3. M's randomness is independent of everything else, so S ⊥ y* given (D, x*). Then
  I(y*; D, S | x*) = I(y*; D | x*), and the chain rule gives the identity. ∎

  Consequence. For a fixed prior, ε ↦ I(y*; D | x*, S_ε) is the exact price of privacy for
  "release with M, then do anything". The noise-aware PFN attains this price, so a trained
  PFN can rank release mechanisms at equal ε by their downstream Bayes risk. That is open
  question T5.

  Proposition D2 (naive plug-in is miscalibrated). Feeding DP outputs to a standard PFN
  targets P(y* | x*, D = S), which treats noise as signal. The direction of the error depends on
  M:

          Label randomized response flattens the naive predictive toward uniform. With binary
          flip rate ρ it estimates (1 − 2ρ)p + ρ, so it is under-confident.
          DP synthetic rows generated in bulk make it over-confident, since every synthetic
          row is counted as real evidence.

  The noise-aware target corrects both.

  6. Theory E: DP-PFN on graphs
  On a graph, the PFN's context is a set of labelled nodes plus the whole graph. Privacy
  therefore splits by what changes: a label, an edge or a whole node. Label-DP and edge-DP
  have clean DP-PFN mechanisms. Node-DP remains hard.

  What NodePFN computes. NodePFN (ICLR 2026) fuses three terms in every layer:
  H^{ℓ+1} = LayerNorm(H^ℓ + Attn + GCN(H^ℓ, Ã)). Here Ã = D^{−1/2} A D^{−1/2} is the
  symmetric-normalized adjacency. Context-node labels enter as an added label
  embedding, and test nodes cross-attend only to context nodes.




                                                                                                               Page 11 of 25
DP-PFN: Differentially Private Prior-Data Fitted Networks




  Two features of the pipeline also touch the graph: an optional feature-smoothing step that
  sums over edges, and a 32-member ensemble over feature order and scaling.

  G1. Label-DP: graph-shard voting. Split the labelled nodes into T disjoint groups. Teacher t
  runs the PFN on the full graph and all features, which are public under label-DP, but uses
  only group t's labels as context. One label change moves one teacher, so Mechanism C1
  and Theorem C2 apply unchanged.

  On graphs, sharding splits only the labels: every teacher keeps all edges and features.
  Structural signal is not lost the way it is when tabular rows are sharded. For release mode
  R2, privately pseudo-label every unlabelled node once (a graph PATE), then run NodePFN
  freely on the result.

  G2. Edge-DP: noisy aggregation inside the PFN. Replace each GCN step with a sum over
  unit-norm states, plus Gaussian noise:

     \tilde{A}_\ell = A\,\mathrm{N}(H^{\ell}) + Z_\ell,\quad Z_\ell \sim
     \mathcal{N}(0, \sigma^2 I), \qquad \mathrm{N}(h) = h/\max(1, \|h\|_2)


  Lemma G2. Fix everything released before layer ℓ. Under edge-DP, H^ℓ is then a function
  of public features, public labels and earlier noisy releases, so it is identical on
  neighbouring graphs. Adding or removing edge (u, v) changes rows u and v of A·N(H^ℓ) by
  at most 1 each, so the ℓ₂ sensitivity is √2.

  Each layer is a Gaussian mechanism with Rényi-DP α/σ², and one forward pass costs Lα/
  σ². That single pass yields predictions for every node, so per-node queries are free.

  This is GAP's aggregation perturbation (Sajadmanesh et al., 2023) moved inside an in-
  context learner. GAP then trains a classifier per graph on cached noisy aggregates. DP-
  NodePFN replaces that training with a forward pass whose weights saw the same noise in
  the prior.

  G2 requires four changes to NodePFN:

      1. Drop symmetric normalization, which depends on private degrees. DPDGC shows
         standard graph convolutions need noise growing at least linearly with maximum
         degree.
      2. Make the 32-member ensemble reuse one set of noisy aggregates, or pay for each
         member.
      3. Noise or remove the edge-based feature-smoothing preprocessing.
      4. Retrain on the prior with the same noise injected (noise-aware, Section 5). Without it,
         the noise is out of distribution.



                                                                                           Page 12 of 25
DP-PFN: Differentially Private Prior-Data Fitted Networks




  G3. Edge-LDP: randomized response on adjacency. If every node pair is flipped with
  probability ρ = 1/(1 + e^ε), a cSBM stays a cSBM. Only its parameters move:

     p' = \rho + (1 - 2\rho)\,p \quad (p \in \{p_{\mathrm{in}},
     p_{\mathrm{out}}\}), \qquad p'_{\mathrm{in}} - p'_{\mathrm{out}} = (1 -
     2\rho)(p_{\mathrm{in}} - p_{\mathrm{out}})


  The noise-aware prior is therefore the same prior family with transformed parameters,
  which makes it easy to simulate. The cost is density. With N = 1,024 and ε = 2 (ρ ≈ 0.119),
  RR adds about 61,000 fake edges, against NodePFN's synthetic-graph average of about
  12,700 real ones.

  Proposition G3 (heuristic detectability threshold). Write a = Np_in and b = Np_out for K
  balanced communities. Apply the Kesten–Stigum condition (a' − b')² > K(a' + (K − 1)b') to
  the randomized graph. Structure-only community signal then requires roughly:

     N \;\lesssim\; \frac{(1-2\rho)^2\,(a-b)^2}{K^2\,\rho}


  Example: K = 2, a = 20, b = 4 and ε = 2 give N below about 310. Larger graphs must take
  their signal from features, labels, or degree side-information, as in Blink (CCS 2023). Blink
  derives a Bayesian edge denoiser by hand. A noise-aware NodePFN would learn the full
  posterior predictive instead. Making this threshold rigorous is plan item T7.

  G4. Node-DP: the hard case. Changing one node alters its features, its label and up to d of
  its edges. Every neighbour's aggregate moves, so sensitivity grows with a degree bound
  d_max (GAP's node-level variant; DPDGC). A DP-NodePFN route combines three parts:

          degree-bounded noisy aggregation, with the same truncation used in the prior;
          context sharding over disjoint node groups for raw features and labels;
          attention restricted to the teacher's own shard plus the shared noisy aggregates.

  The total cost is the aggregation cost plus the vote cost, by composition. As in GAP, the
  analysis must state whether a node's own features may be used in its own prediction.

  TabPFN: what to watch.

      1. Preprocessing leaks. In C1, each teacher fits its transforms on its own shard, so the
         shard's accounting covers them. Single-context mechanisms (A5, A6) and student-
          query generation (C4) need public feature bounds or a DP estimate of them.
      2. Ensembling is free. Random feature and class permutations, preprocessing variants
         and the 64 learned "thinking rows" in 2.5 are all data-independent, as long as each
          member sees only its own shard.
      3. Shards fit the model's sweet spot. Theorem C2 says the best shard size m sits where
         the learner's error curve flattens. TabPFN is strongest on small tables, which is exactly
         the regime C2 rewards.
      4. Queries do not see each other. Many queries can share one pass with no cross-query
         mixing inside the model. Each answer is still a separate release in mode R1.
      5. Retraining is feasible at small scale. Retraining TabPFN-2.5 from scratch is out of
         reach for most labs. Small TabPFN-style learners can be trained with open tooling
         such as TFM-Playground (used in a dataset-inference study). Continued pretraining
         of TabPFN-2.5 on synthetic-only tasks has also been demonstrated (TREDBench), and
          it keeps Proposition 0 intact.

  NodePFN: what to watch.

      1. Label-DP works today. Graph-shard voting (G1) needs no retraining, and every
          teacher keeps the full graph.
      2. Edge-DP needs the four G2 changes: sum aggregation, shared noisy aggregates
         across the 32 ensemble members, no unprivatized smoothing, and noise-aware
          retraining.

DP-PFN: Differentially Private Prior-Data Fitted Networks




      3. Scale is unclear. Pretraining uses 1,024-node graphs. The paper reports results on
         graphs up to 48,921 nodes (Questions) without explaining how inference scales. Any
          subgraph sampling must be data-independent or counted, as with degree-bounded
          sampling under node-DP.
      4. No privacy or label-noise analysis. The paper discusses neither. Its prior already
          spans homophily 0.1–0.9 plus Erdős–Rényi graphs, so the RR-shifted homophily in G3
          stays inside a familiar prior family.

  A cheap graph baseline from the tabular side. Treating nodes as rows with structural
  features is an established way to run TabPFN on graphs. Under edge-DP, those structural
  features must be private. Using G2's noisy aggregates as features for an unmodified
  TabPFN gives a simple baseline: "GAP features + TabPFN". Comparing it with noise-aware
  DP-NodePFN isolates the value of noise-aware training.


  8. Q3: advantages over prior DP tabular and graph methods
  DP-PFN's advantages come from three facts:

          the weights are free;
          there is nothing to train or tune on private data;
          the learner is near Bayes-optimal on small data, which is where DP hurts most.

  Its weaknesses are the certification gap, per-query cost in mode R1, context-size limits,
  and node-DP. Each advantage below says whether it is proved here, holds by construction,
  or is a hypothesis for an experiment (Section 10).

  Compared methods. On tables: DP-SGD on neural nets; DP boosting (DP-EBM); PATE and
  private prediction; DP synthetic data then non-private training (AIM, MST, PrivBayes, Tab-
  PE); DP in-context learning with LLMs (DP-ICL, DP-TabICL); and TabPATE. On graphs: GAP,
  ProGAP, DPDGC, node-level DP-SGD (Daigavane et al.), PATE-based PrivGNN, and local-
  DP methods (Blink, LPGNN, Solitude).

  Where DP-PFN is weaker.

      1. Certification. Only the black-box wrappers (Section 4) and noise-aware releases
         (Section 5) carry guarantees. The elegant one-draw mechanisms (Section 2) are exact
         only for the true PPD.
      2. Per-query cost. A DP-SGD model answers unlimited queries once trained. DP-PFN in
         mode R1 pays per answer, unless it switches to R2 (student release) or R3 (noise-
         aware).
      3. Inference compute. Vote and LogPool run T forward passes per query. Distilling into a
         student context (C4) removes this at deployment.
      4. Context limits. Single-context mechanisms see at most 50,000 rows with TabPFN-2.5.
         Sharding handles larger n, but only for the wrapper mechanisms.
      5. Row-DP with continuous features. Section 2 mechanisms need floored feature
          densities (Lemma A4), which may cost utility.
      6. Node-DP. DP-PFN does not remove the degree-dependent sensitivity of graph
         aggregation (G4).
      7. Prior misspecification. When real data sit far from the prior, every advantage shrinks.
         Adapting the prior to the private data would itself cost privacy.

  10. Q4b: research plan, experiments
  Eight experiments test the theory and the claimed advantages. E1 decides early whether
  the exact-PPD mechanisms are usable in practice. E2–E4 make up the tabular paper, E5–
  E6 the graph paper, and E7–E8 run across both.

  Shared setup.

          Models. Small PFNs trained in-house on four kinds of prior:
                  closed-form priors;
                  floored priors with η as an input;
                  clean-target variants (A5, A6);
                  noise-aware variants (label RR, Gaussian marginals, noisy graph aggregates).
                  Released synthetic-only TabPFN checkpoints serve as teachers. NodePFN serves
                  as is (label-DP) and retrained with sum aggregation and noise (edge-DP).
          Tabular data. OpenML-CC18 and the TabArena-lite classification subset, plus privacy-
          relevant tables: Adult, ACS Income and Employment (folktables), credit default, bank
          marketing, and Diabetes 130-US hospitals. Subsample to n ∈ {500, 2k, 10k, 50k}.
          Graph data. Homophilous: Cora, Citeseer, Pubmed, Amazon-Photo, Coauthor-CS.
          Heterophilous: Chameleon, Squirrel, Actor, Amazon-Ratings, Tolokers. DP-GNN
          standards: Facebook, Amazon, LastFM. Reddit only if inference scales.
          Privacy levels. ε ∈ {0.5, 1, 2, 4, 8}, with δ below 1/n. Report label-, row-, edge- and node-
          level results separately.
          Metrics. Accuracy and AUROC; NLL and expected calibration error; total ε including
          tuning; wall-clock and forward passes; empirical privacy from attacks (E7).
